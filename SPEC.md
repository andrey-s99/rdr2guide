## 1. Цель и контекст

Пользователь играет в Red Dead Redemption 2 (сюжетный режим) и охотится, чтобы изготавливать вещи у трёх персонажей:

- **Охотник** (Trapper) — одежда, костюмы, украшения для шляп, сёдла.
- **Пирсон** (Pearson) — сумки и украшения лагеря.
- **Скупщик** (Fence) — безделушки и талисманы.

В игре неудобно быстро посмотреть: какие шкуры для чего нужны, где искать животных, сколько всего шкур нужно на набор. Приложение решает это.

**Пользователь один**, приложение только для него. Открывает его на Android-телефоне прямо во время игры, часто одной рукой. Публикации в магазинах нет.

**Что приложение ДОЛЖНО уметь:**

1. Показать списки вещей у каждого торговца, с рецептом у каждой.
2. Отдельно показать 16 костюмов Охотника: из каких частей состоят, какие части уже есть, отметить костюм целиком.
3. Показать карточку животного: где искать, чем убивать для идеальной шкуры, повадки, ссылки на карты, для каких вещей нужно.
4. Отмечать изготовленные вещи.
5. Вести запасы материалов («что у меня на руках»). При отметке «изготовлено» материалы списываются, с возможностью отменить.
6. Считать сводку: сколько каких материалов ещё нужно — для всего сразу, для торговца, для всех костюмов, для одного костюма, для выбранных целей.
7. Режим «Цели»: пользователь отмечает звёздочкой вещи и костюмы, которые хочет сейчас, и получает список охоты по ним, сгруппированный по регионам.
8. Работать офлайн, сохранять прогресс в телефоне, выгружать и загружать резервную копию.

## 2. Глоссарий

| Термин | Значение |
|---|---|
| Торговец (vendor) | Охотник, Пирсон или Скупщик. |
| Предмет (item) | То, что изготавливает торговец: шляпа, сумка, безделушка и т. д. |
| Костюм (outfit) | Набор из 4–5 предметов Охотника. Сам костюм не изготавливается — он «готов», когда готовы все его части. |
| Материал (material) | То, из чего делается предмет: шкура, перо, туша, рога, часть легендарного зверя, особый предмет. |
| Рецепт (recipe) | Список материалов с количеством для одного предмета. |
| Запас (stock) | Сколько единиц материала есть у пользователя сейчас. Вводит сам пользователь. |
| Расходуемый материал | `consumedOnCraft: true`. При изготовлении списывается. |
| Нерасходуемый материал | `consumedOnCraft: false`. Это шкуры легендарных зверей: одна шкура, проданная Охотнику, открывает все вещи из этого зверя. Не списывается. |
| Область подсчёта (scope) | Набор предметов, по которым считается сводка: «всё», «Пирсон: сумки», «костюм Охотник на медведей», «цели» и т. д. |
| Цель (goal) | Предмет или костюм, отмеченный звёздочкой. |

- Все идентификаторы (`id`) — латиница в `snake_case`, уникальны внутри файла.

### 7.1. Состояние пользователя (то, что сохраняется)

```ts
export interface CraftRecord { at: string; deducted: Record<string, number> } // ISO-дата; сколько реально списали
export interface UserState {

  stock: Record<string, number>;          // ключ — material.id; отсутствие ключа = 0
  goals: { items: string[]; outfits: string[] };
  settings: { theme: 'night' | 'paper' | 'system'; showEnglish: boolean };
}
```

Начальное состояние: всё пусто, `theme: 'night'`, `showEnglish: true`.

### 7.2. Статус предмета

```
status(item) =
  'crafted'  — если item.id есть в crafted
  'ready'    — иначе, если для каждой записи рецепта stock[materialId] >= qty
  'missing'  — иначе
shortfall(item) = Σ по рецепту max(0, qty − stock[materialId])   // показывается как «не хватает N»
```

Для нерасходуемого материала (`consumedOnCraft: false`) условие то же: `stock >= qty` (qty у них всегда 1).

`locked(item)` = `prerequisiteItemIds` не пуст и хотя бы один из них не изготовлен. Блокировка ТОЛЬКО информационная: показывается пометка, но отметить предмет можно.

### 7.3. Статус костюма (вычисляется, не хранится)

- `craftedParts` = число частей со статусом `crafted`; `totalParts` = `itemIds.length`.
- Костюм «собран», если `craftedParts === totalParts`.

### 7.4. Потребность в материалах для области подсчёта

Вход: список предметов области `S`, `stock`, `crafted`.

```
need(m):
  если m.consumedOnCraft:
      need(m) = Σ qty по всем НЕизготовленным предметам из S, где m есть в рецепте
  иначе (шкура легендарного зверя):
      need(m) = 1, если хотя бы один НЕизготовленный предмет из S использует m, иначе 0
have(m)      = stock[m] (0, если нет)
remaining(m) = max(0, need(m) − have(m))
```

В сводку попадают материалы с `need(m) > 0`. Строки с `remaining = 0` показываются только при включённом переключателе «Показывать собранное».

Итоги области: `distinct` = число материалов с `remaining > 0`; `units` = Σ `remaining`.

### 7.6. Отметка «изготовлено» и списание

`markCrafted(itemId)`:
1. Если уже изготовлен — ничего не делать.
2. Для каждой записи рецепта с `consumedOnCraft: true`: `d = min(stock[m], qty)`; `stock[m] -= d`; если `d > 0` — записать `deducted[m] = d`.
3. Нерасходуемые материалы не трогать.
4. Записать `crafted[itemId] = { at: now, deducted }`.
5. Показать тост (раздел 9.10) с кнопкой «Отменить».

`unmarkCrafted(itemId)`:
1. Для каждой пары в `crafted[itemId].deducted`: `stock[m] += d`.
2. Удалить `crafted[itemId]`.

Отмена из тоста = `unmarkCrafted`. Снять отметку можно и позже (галочкой) — результат тот же: материалы возвращаются ровно в том количестве, в котором были списаны.

`markOutfitCrafted(outfitId)`: вызвать `markCrafted` для каждой неизготовленной части в порядке `itemIds`; один общий тост, «Отменить» снимает все эти отметки в обратном порядке.

Запас: целое число от 0 до 999. Кнопки «−» и «+», долгое нажатие не нужно. Поле можно тапнуть и ввести число с цифровой клавиатуры (`inputmode="numeric"`).

### 7.7. Поиск (`src/logic/search.ts`)

- Нормализация: нижний регистр, `ё` → `е`, обрезка пробелов, схлопывание повторных пробелов.
- Поиск по подстроке в `nameRu` и `nameEn` предметов, костюмов, животных, материалов.
- Начинать искать с 2 символов. Результаты группами: Костюмы, Предметы, Животные, Материалы; в каждой группе не больше 20, сортировка: сначала совпадение с начала слова, потом по алфавиту `nameRu`.

## 9. Экраны

Общие правила для всех списков:
- Строка списка не ниже 56 px, весь ряд — зона нажатия, ведёт на карточку.
- Галочка «изготовлено» и звёздочка «цель» — отдельные зоны нажатия не меньше 44×44 px, не открывают карточку.
- Над списком — фильтр-чипсы: «Все», «Не сделано», «Готово к крафту», «Сделано». По умолчанию «Не сделано». Выбор запоминается на сессию (в памяти) для каждого экрана.
- Пустое состояние: короткий текст по-русски, например «Здесь пока пусто — всё изготовлено».

### 9.1. Охотник → Костюмы

- Ссылка-строка «Где найти Охотника и как он работает →» ведёт на `#/vendor/trapper`.
- Карточки 16 костюмов в порядке `outfits.json`. В карточке: название RU (крупно), EN (мелко), прогресс «3 / 5 частей» и полоска прогресса, строка «Осталось добыть: 7 шт.» (= `units` области `outfit:<id>`), звезда цели. Собранный костюм — с отметкой «Собран» и приглушённый.

1. Заголовок RU/EN, звезда цели, прогресс.

3. Кнопка «Отметить весь костюм изготовленным» (видна, если есть неизготовленные части) → `markOutfitCrafted` с подтверждением: «Отметить N частей изготовленными? Материалы будут списаны из запасов».

### 9.3. Охотник → Предметы

- Группы по категориям в порядке `vendor.categories`; у группы заголовок с иконкой и счётчиком «сделано X из Y». Группы сворачиваются (состояние в памяти).
- Строка предмета: иконка категории, название RU + EN, цена, мини-рецепт (чипсы «Бобр ×2», «Корова ×1»; цвет чипса: зелёный — хватает, обычный — не хватает), статус, звезда, галочка.
- Если предмет входит в костюмы — маленькая метка с названием костюма.

### 9.4. Карточка предмета `#/item/<id>`

Блоки сверху вниз (пустые блоки не показывать):
1. Иконка категории, название RU/EN, торговец и категория, цена. Звезда цели.
2. Предупреждение о данных (если `dataConfidence` не `high`) — жёлтая плашка с `dataNoteRu`.
3. «Условие»: `requirementRu`; для предметов с `prerequisiteItemIds` — пометка «Сначала изготовьте: …» со списком и прогрессом.
4. «Эффект»: `effectRu`. «Место в лагере»: `campSpotRu`.
5. «Рецепт» — таблица: материал (название, тип-пометка: «идеальная», «любая», «легендарная»), «нужно» qty, «есть» со степпером, кнопка-ссылка на животное «Где добыть →». Для нерасходуемых — пометка «не расходуется».
6. «Входит в костюмы» — ссылки.
7. Большая кнопка внизу: «Отметить изготовленным» или «Снять отметку» (снятие — с подтверждением «Вернуть списанные материалы в запасы?» и перечнем).

### 9.5. Пирсон → Сумки, Пирсон → Лагерь

- Сверху ссылка «Как работает Пирсон →» (`#/vendor/pearson`) и одна строка-напоминание: «Пирсон работает до конца главы 6».
- Сумки: строки как в 9.3, плюс одна строка с `requirementRu` под названием. «Легенда Востока» — с пометкой блокировки по 7.2.
- Лагерь: строки как в 9.3, плюс `campSpotRu`. Группировка по `campSpotRu` в порядке первого появления в данных.
- Кнопка внизу: «Сводка по Пирсону» → `#/summary?scope=pearson`.

### 9.6. Скупщик → Безделушки, Скупщик → Талисманы

Строки как в 9.3, плюс `effectRu` второй строкой. Сверху ссылка «Как работает Скупщик →» (`#/vendor/fence`). Цена не показывается (null).

### 9.7. Звери `#/animals`

- Переключатель: «Обычные» / «Легендарные» / «Птицы».
- Фильтр-чипсы регионов (мультивыбор; ничего не выбрано = все) и переключатель «Только нужные» (по умолчанию включён: показывать животных, у которых хотя бы один материал имеет `remaining > 0` в области `all`).
- Строка животного: иконка по типу (лапа / птица / рогатый череп для легендарных), название RU + EN, чипсы регионов, значок опасности (`aggressive` — жёлтый, `dangerous` — красный), значок «Эпилог», если `availability = epilogue`, справа бейдж «нужно N» (Σ `remaining` его материалов в области `all`).
- Сортировка: по убыванию «нужно N», при равенстве — по `nameRu`.
- Для легендарных вместо бейджа — статус: «Шкура у Охотника ✓», если `stock` шкуры ≥ 1, иначе «Не добыт».

### 9.8. Карточка животного `#/animal/<id>`

1. Название RU/EN, тип, размер, значки опасности и эпилога, `availabilityNoteRu`.
2. «Где искать» — `habitatRu`; чипсы регионов.
3. «Чем убивать для идеальной шкуры» (для легендарных — «Тактика») — `perfectKillRu`.
4. «Повадки и советы» — `behaviorRu`. Для легендарных — ещё «Когда доступен» — `unlockRu`.
5. «Карты и гайды» — кнопки-ссылки из `links`, затем ссылки `meta.globalMapLinks`. Открываются во внешнем браузере (`target="_blank" rel="noopener"`). Рядом иконка «внешняя ссылка».
6. «Материалы с этого зверя» — для каждого материала с этим `animalId`: название, `sourceRu`, степпер запаса, «нужно всего / осталось» (область `all`), и раскрывающийся список «Для чего нужно»: предметы, где он в рецепте — название, торговец, qty, статус; изготовленные приглушены. Тап → карточка предмета.

### 9.9. Сводка `#/summary`

Главный экран для подготовки к охоте.

- **Выбор области**: выпадающий список (нативный `<select>`, оптгруппы: «Общее», «Охотник», «Костюмы», «Пирсон», «Скупщик»). Все области из 7.5, у `outfit:<id>` — 16 пунктов, у `trapper_cat:<id>` — 8 пунктов. Если целей нет, пункт «Цели» показывает пустое состояние «Отметьте звёздочкой вещи или костюмы».
- Значение по умолчанию при первом открытии: `goals`, если есть цели, иначе `all`. Последние выбранные область и группировка запоминаются в `localStorage` под отдельным ключом `rdr2-hunter:ui` в виде `{ "summaryScope": string, "summaryGroup": "animal" | "region" | "flat" }`. Этот ключ не входит в резервную копию. Если сохранённая область больше не существует — использовать `all`.
- **Группировка**: переключатель «По зверям» (по умолчанию) / «По регионам» / «Списком».
  - По зверям: группа = животное (заголовок: название, основной регион, бейдж Σ remaining, тап по заголовку → карточка животного), внутри — его материалы. Особые предметы (`animalId = null`) — в группе «Особые предметы».
  - По регионам: группа = `animal.regions[0]` в порядке `regions.json`, внутри — группы зверей как выше. Особые предметы — отдельная последняя группа. Под названием зверя мелко — остальные регионы из `regions`.
  - Списком: все материалы одной таблицей, сортировка по убыванию `remaining`.
- **Строка материала**: название, крупно `remaining`, мелко «нужно X · есть Y», степпер запаса. Тап по строке → раскрывающийся список «для чего» (как в 9.8, но только предметы из текущей области).
- Переключатель «Показывать собранное» (строки с `remaining = 0`), по умолчанию выключен.
- Сверху — итог: «Осталось добыть: **N** шт., **K** видов материалов» и прогресс области: «Изготовлено X из Y предметов».
- Сортировка групп: по убыванию суммарного `remaining`, при равенстве — по `nameRu`.

### 9.10. Тост «Отменить»

Появляется над нижней навигацией на 6 секунд. Текст: «Изготовлено: <название>» (или «Костюм: <название>, N частей»), вторая строка — что списано («Бобр −2, Корова −1») или «Ничего не списано». Кнопка «Отменить». Новый тост заменяет старый (старое действие остаётся в силе). Тост не перекрывает кнопки навигации.

### 9.11. О торговце `#/vendor/<id>`

`nameRu`, «Где найти» (`locationsRu` списком), «Как работает» (`rulesRu` списком), прогресс «Изготовлено X из Y», ссылки на подразделы и на сводку торговца.

### 9.12. Поиск `#/search`

Поле ввода в шапке с автофокусом, кнопка очистки. Результаты по 7.7. Пока введено меньше 2 символов — подсказка «Введите название вещи, зверя или шкуры». Нет результатов — «Ничего не найдено».

### 9.13. Настройки `#/settings`

- Тема: «Ночь» (по умолчанию) / «Бумага» / «Как в системе».
- «Показывать английские названия» — переключатель.
- «Сохранить резервную копию» — скачивает файл `rdr2-hunter-backup-YYYY-MM-DD.json` (раздел 11.2).
- «Загрузить резервную копию» — выбор файла; проверка формата; подтверждение «Заменить текущий прогресс данными из файла?»; при ошибке — понятное сообщение, текущий прогресс не трогать.
- «Сбросить прогресс» — двойное подтверждение (второй диалог требует нажать «Да, удалить всё»).
- «О данных»: версия данных (`meta.dataVersion`), `meta.notesRu`, список `meta.sources` ссылками, количество предметов с пометкой «данные спорные» и ссылка на их список (`#/search` нельзя — сделай простой список прямо в настройках, раскрывающийся).
- Версия приложения (из `package.json`).

## 10. Визуальный стиль

Направление: «микс». Основа — тёмное игровое меню RDR2 (почти чёрный фон, костяной текст, кроваво-красный акцент). Карточки предметов, костюмов и животных выглядят как страницы старого каталога: состаренная бумага, гравюрные рамки, типографские заголовки. - Заголовки разделов и карточек: **Ruslan Display** (fallback — Old Standard TT 700). Только крупные заголовки (≥ 20 px), не для текста.

### 10.3. Детали оформления

- Карточка-«страница»: фон `--paper` с текстурой, двойная тонкая рамка `--brass` (внешняя 1 px, внутренняя 1 px с отступом 3 px), скругление 4 px. Заголовок по центру с декоративными линиями-разделителями по бокам.

- Звезда цели — контурная, при выборе залитая `--brass`.
- Кнопка главного действия — фон `--accent`, текст светлый, Oswald прописными.
- Анимации — только `transform`/`opacity`, ≤ 200 мс; при `prefers-reduced-motion` — без анимаций.

### 10.4. Иконки

Собственные SVG-компоненты в `src/icons/`, единый стиль: «гравюра/штрих», `viewBox="0 0 24 24"`, обводка `stroke="currentColor"`, `stroke-width="1.5"`, без заливки (кроме звезды-выбранной). Нужны: `hat, coat, vest, gloves, boots, chaps, feather, saddle, satchel, camp, trinket, talisman, paw, bird, legendary (рогатый череп), star, check, search, settings, back, plus, minus, warning, external, lock, map-pin, chevron, close`. Значения `category.icon` в данных совпадают с именами иконок. Не копировать иконки из игры или чужих наборов — рисовать простые свои.

`AppShell, TopBar, BottomNav, SegmentedControl, FilterChips, ItemRow, OutfitCard, AnimalRow, RecipeTable, MaterialRow, Stepper, Checkbox, GoalStar, StatusBadge, ProgressBar, DataWarning, ConfirmDialog, Toast, ExternalLink, EmptyState, PaperCard, SectionHeader`.

### 10.6. Адаптивность и доступность

- Основная ширина — 360–430 px. На ширине > 600 px контент центрируется колонкой max 560 px.

## 11. Сохранение и резервные копии

### 11.1. localStorage

- Ключ: `rdr2-hunter:state`, значение — `UserState` (раздел 7.1) в JSON.
- Сохранять с задержкой 300 мс после изменения (debounce) и сразу при `visibilitychange → hidden`.
- При загрузке: если ключа нет — начальное состояние; если JSON битый или `schemaVersion` неизвестен — начальное состояние + тост «Не удалось прочитать сохранение, начато с нуля»; старое значение перед этим скопировать в ключ `rdr2-hunter:state-broken-<timestamp>`.
- Очистка «мусора»: при загрузке удалить из `crafted`, `stock`, `goals` id, которых нет в данных (на случай обновления данных).
- Миграции: функция `migrate(raw): UserState` со switch по `schemaVersion` — сейчас только версия 1.

### 11.2. Резервная копия

Файл:
```json
{ "app": "rdr2-hunter", "exportedAt": "<ISO>", "dataVersion": "1.0.0", "state": { ...UserState } }
```
Импорт принимает только файлы с `app === "rdr2-hunter"` и валидным `state` (проверка типов вручную, без библиотек), затем применяет очистку из 11.1.

### 15.2. Расчёты и списание (`tests/calc.test.ts`, `tests/store.test.ts`)

1. **Легендарная шкура считается один раз.** Область `outfit:bear_hunter`, пустой прогресс → `legendary_bear_pelt` need = 1 (хотя нужна трём предметам).
2. **Статус.** `stock = { perfect_boar: 1, perfect_rabbit: 2 }` → `boar_riding_gloves` = `ready`; `stock = { perfect_boar: 1, perfect_rabbit: 1 }` → `missing`, shortfall = 1.
3. **Списание не уходит в минус.** `stock = { perfect_boar: 1, perfect_rabbit: 1 }`, `markCrafted('boar_riding_gloves')` → stock `perfect_boar: 0`, `perfect_rabbit: 0`; `deducted = { perfect_boar: 1, perfect_rabbit: 1 }`.
4. **Отмена возвращает ровно списанное.** Продолжение п. 3: `unmarkCrafted` → `perfect_boar: 1`, `perfect_rabbit: 1`.
5. **Нерасходуемое не списывается.** `stock = { legendary_bear_pelt: 1 }`, `markCrafted('legendary_bear_head_hat')` → `legendary_bear_pelt` остаётся 1, `deducted = {}`.
6. **Изготовленное не учитывается.** После п. 5 область `outfit:bear_hunter`: `legendary_bear_pelt` remaining = 0 (запас 1), `perfect_bison` need = 1, `perfect_bull` need = 1.
7. **Костюм целиком.** Пустой запас, `markOutfitCrafted('bear_hunter')` → 4 предмета изготовлены, костюм собран; отмена тоста → 0 изготовлено.
8. **Цели.** `goals = { items: ['moccasins'], outfits: ['wrangler'] }` → область `goals` содержит 6 предметов (5 частей + мокасины; `two_toned_moccasins` и `moccasins` — разные предметы).
9. **Поиск.** «чёрн» и «черн» дают одинаковый результат и находят животное «Чёрный медведь»; «бобр» находит животное «Бобр», материал «Идеальная шкура бобра» и предметы с «бобр» в названии.
10. **Очистка устаревших id.** Загрузка состояния с `crafted: { unknown_item: … }` → ключ удалён.

## 17. Решения по умолчанию

| Ситуация | Решение |
|---|---|
| Длинное название не помещается | Перенос на 2 строки, дальше многоточие; полное название — в карточке. |
| Предмет есть в нескольких костюмах | Сейчас таких нет; код всё равно ДОЛЖЕН поддерживать массив `outfitIds`. |
| Пользователь ставит запас больше, чем нужно | Разрешено; `remaining` = 0, лишнее не показывается как ошибка. |
| Отметили «изготовлено» без материалов | Разрешено; списывается то, что есть; тост «Ничего не списано». |
| Звезда цели у изготовленного предмета | Можно поставить, но в области «Цели» он ничего не добавляет. |
| Звезда у собранного костюма | Аналогично. |
| Сортировка внутри категорий предметов | Как в `items.json`. |
| Нет описания у поля в данных (пустая строка) | Блок не показывать. |
| Пользователь открыл несуществующий id | Экран «Не найдено» с кнопкой «На главную». |
| Двойной тап по галочке | Обрабатывать как два отдельных действия (отметить → снять с возвратом материалов). |
| Нужен текст, которого нет в ТЗ | Короткий, нейтральный, на «вы», без восклицательных знаков. |
